# Turbo Vision 1.0 for Linux (GCC, C++11) and Windows (MSVC)

A port of the Borland Turbo Vision library (Borland C++ 3.1, DOS) to Linux.
Programs run in any xterm-compatible terminal, including over ssh. They detect
the window size themselves and re-layout when the window is resized. The same
sources also build on Windows 10 and later with Visual Studio, where the
programs run in the console (see [Windows](#windows)).

The original files (`../tvision-original/INCLUDE`, `../tvision-original/SOURCE`, `../tvision-original/DEMOS`, ...) are left unchanged. Everything ported lives in this directory.

## Origin

Turbo Vision was created by [Borland International](https://en.wikipedia.org/wiki/Borland)
and shipped with Borland C++ 3.1 (1992); see [Turbo Vision](https://en.wikipedia.org/wiki/Turbo_Vision)
on Wikipedia. Borland's development tools now belong to
[Embarcadero Technologies](https://www.embarcadero.com/). The original code is
Copyright © 1991 Borland International; the copyright notices in the
source files are kept. This port is an independent project and is not
affiliated with or endorsed by Borland or Embarcadero.

Programmer's documentation (HTML): `doc/index.html` — a class reference with
the class hierarchy and examples (`doc/classes.html`) and a guide to porting
programs from the DOS version (`doc/porting.html`). It is generated by
`python tools/mkdoc/mkdoc.py`; `tools/mkdoc/check_examples.py` checks that the
examples compile.

## Building

You need `g++` (any version with C++11; tested with GCC 13 and GCC 15) and GNU make.
There are no other dependencies; ncurses is not required.

```sh
make            # lib/libtv.a, lib/libtvaddons.a, bin/tvdemo, bin/tvedit, bin/tvforms,
                # bin/tvhc, bin/hello, bin/yamledit, bin/tvguid*, bin/keytest;
                # bin/phonenum.tvf and bin/parts.tvf
make check-help # compiles help/demohelp.txt and compares it with the DOS DEMOHELP.HLP
make check-addons  # tests of the add-on classes
make lib        # the libraries only
make DEBUG=1    # -O0 -g
make ASAN=1     # AddressSanitizer + UBSan
make clean
```

Link your own program like this:

```sh
g++ -std=c++11 -Ipath/include -Ipath/include/compat app.cpp \
    -Wl,--whole-archive path/lib/libtv.a -Wl,--no-whole-archive -o app
```

`--whole-archive` is required because stream classes (`TStreamableClass`) are
registered by static constructors, just as in the DOS version.

### Windows

The same sources build on Windows 10 and later with Visual Studio (MSVC,
2022 or later) through CMake; only the terminal driver differs
(`source/platform/win32/` instead of `source/platform/posix/`). The Makefile
stays the way to build on Linux.

```bat
cmake -B build                          :: finds Visual Studio
cmake --build build --config Release    :: lib/tv.lib, lib/tvaddons.lib, bin/*.exe
ctest --test-dir build -C Release       :: the tests of the add-ons
```

Visual Studio can also open the directory as it is (File > Open > Folder).
Link your own program with `/WHOLEARCHIVE:tv.lib` (the reason is the one
above); `CMakeLists.txt` shows how. The programs run in Windows Terminal and
in the console window (`cmd.exe`, PowerShell). On Windows:

- the console gives the state of Shift, Ctrl and Alt with every key, so
  Shift+arrows select in the editor in any console;
- paths have drive letters: inside the library they are written with `/`
  (`C:/Users/...`), which Windows takes; `\` typed in a dialog is accepted;
- `long` is 4 bytes, as in DOS (8 on Linux): data files that a program
  writes with `sizeof( long )` (the TVFORMS ones) differ between the two.

## Running

```sh
cd bin
./tvdemo        # demo (F1 help reads the original DEMOHELP.HLP)
./tvedit        # editor
./hello
./tvguid10      # tutorial examples; 06-16 display their own .cpp from docdemos/
./tvforms       # form editor: F3 opens phonenum.tvf or parts.tvf
./tvhc ../help/demohelp.txt   # help compiler: .txt -> .hlp + .h
./yamledit ../addons/demos/sample.yaml   # TVEDIT with YAML syntax colouring
```

## Add-ons

[`addons/`](addons/README.md) holds new classes built on the library, in a
library of their own (`lib/libtvaddons.a`, header `tvaddons.h`):

- `TAdvancedEditor`: a `TFileEditor` where Ctrl+C, Ctrl+X, Ctrl+V and Ctrl+A
  copy, cut, paste and select all, Ctrl+B selects with the cursor keys
  without Shift (as F3 in Midnight Commander), Ctrl+G goes to a line, Ctrl+F
  searches as you type, the pair of a bracket is shown, and the mouse wheel
  scrolls;
- `TLineNumbers`: line numbers left of the editor, with marked lines;
- `TColoredEditor`: the base of syntax colouring editors (`scanLine()`,
  `classColor()`);
- `TYamlEditor`: a `TColoredEditor` with YAML syntax colouring, and
  `TYamlEditWindow`, a `TEditWindow` that uses it;
- `editorDialogs()`: the Find, Replace, Go to line, Save and error dialogs of
  the editors;
- `TLogView`: a log of lines added at the end, with colours, a limit and
  scrolling that follows the end;
- `TTableView` and `TTableHeader`: a table with columns, sorting by a click
  on the title and marked rows;
- `TValidatedInputLine` with `TRangeValidator`, `TFilterValidator`,
  `TLookupValidator`, `TRegexValidator` and `TFuncValidator`: input lines
  that check what is typed.

### Environment variables

| Variable | Meaning |
|---|---|
| `TVCODEPAGE` | Internal 8-bit code page: `437` (default, as in DOS), `866` (Russian Cyrillic) or `1125` (Ukrainian, with Ґ ґ Є є І і Ї ї). |
| `TVMONO=1` | Monochrome palette. `TERM=dumb` and `TERM=vt100` enable it too. |

Output is always UTF-8. Code-page bytes are converted to Unicode (frames,
░▒▓, ☺♥, ≡ etc.), and UTF-8 typed on the keyboard is converted back to a
code-page byte. Characters missing from the code page are ignored.

## Terminal

- **Size:** taken from `TIOCGWINSZ`; if unavailable, from `$COLUMNS`/`$LINES`; otherwise 80×25. After `SIGWINCH` the desktop, menu bar, status line and windows (`gfGrowRel`) are recalculated. Dialogs without `growMode` keep their size and are only clipped.
- **Mode:** raw, alternate screen, auto-wrap off. The previous terminal state is restored on exit, on a crash (`SIGSEGV` etc.), and on `SIGTERM` and `SIGHUP`. Ctrl-C, Ctrl-S, Ctrl-Q and Ctrl-Z reach the program as ordinary keys, as in the DOS editor.
- **Keys:** xterm, rxvt and Linux console escape sequences are translated to BIOS codes from `tkeys.h`: F1–F12, arrows, Home/End/PgUp/PgDn/Ins/Del with Shift/Ctrl/Alt, Shift-Tab. Alt+letter arrives as `ESC`+letter. With a Cyrillic keyboard layout Alt+«а» works as Alt-F, because the key's ЙЦУКЕН position is used. A lone Esc is recognised after 40 ms.
- **Shift state** (Shift+arrow selection in the editor, `dragGrow`) comes from the modifiers of the last key: `TEventQueue::getShiftState()`. Some terminals (PuTTY with its defaults, for one) send Shift+arrows as plain arrows; then select with Ctrl+K B in any editor, or Ctrl+B in `TAdvancedEditor` (see [`addons/`](addons/README.md)).
- **Mouse:** the xterm SGR protocol (1006) with button and drag tracking (1002). Double clicks and auto-repeat work. The wheel gives `evMouseWheel` events (see below); TV 1.0 had no wheel, so its own views ignore them.
- **Output:** compared with the previous frame, so only changed cells are sent. When nothing changes the program writes nothing, so there is no ssh traffic.
- **Diagnostics:** `bin/keytest` shows which key codes and mouse events your terminal sends.
- **Windows console:** the same output (escape sequences, UTF-8, only changed
  cells). Keys and the mouse come as console events (`ReadConsoleInput`) and
  are turned into the same codes; Shift, Ctrl and Alt are known with every key.
  The size is that of the visible window. If stdin or stdout is redirected, the
  driver opens the console itself (`CONIN$`, `CONOUT$`). Ctrl-Break and closing
  the window restore the console.

## Differences from the DOS version

- **Paths:** the separator is `/`, there are no drives, and the directory tree starts at `/`. `*.*` means "all files". `~/` expands to `$HOME`. File names are case-sensitive. On Windows paths have drives and are written with `/` inside the library (`C:/Users/...`); the tree starts at `C:/`, and `~/` is `%USERPROFILE%` when `HOME` is not set; `rootLength()` in `tvcompat.h` gives the length of the root (`/`, `C:/`).
- **TFileEditor:**
  - LF files are converted to CR LF on load and saved back with LF. CR LF files are saved as they were.
  - A UTF-8 file whose characters all exist in the code page is edited in that code page and saved as UTF-8. Otherwise the file is edited byte for byte.
  - The backup copy is named `name.ext.bak`.
  - The file size limit is 64 KB, as in the original: editor positions are `ushort`.
- **Streams (`fpstream`, resources, `.HLP`):** the on-disk format is still the DOS one: `int` is 16 bits, `long` is 32 bits, little-endian. So the original `DEMOHELP.HLP` is read unchanged.
- **TParamText:** the data record is interpreted by the library itself, because it cannot be passed to `vsprintf` as a `va_list` on x86-64. Each parameter occupies a `long`-sized slot: a number for `%d %u %x %c` or a pointer for `%s`.
- **The DOS Shell item** in the demos runs `$SHELL` (or `/bin/sh`) on the normal screen.
- **`TSystemError`:** a stub. There are no DOS critical-error or Ctrl-Break handlers.
- **Graphics:** the BGI demos (TVBGI, TVGUID20/21) are not ported.
- **TVFORMS:** the data files `phonenum.tvf` and `parts.tvf` are created by `bin/genphone` and `bin/genparts` (in DOS this was done by `GENFORMS.MAK`); `make` runs them itself. Form records are stored in the Linux memory layout (`long` = 8 bytes), so DOS `.TVF` files cannot be used and must be regenerated. The backup on save is `name.bak`. The "Video mode" item (25/43/50 lines) only reports that the terminal sets the size.
- **TVHC:** default extensions are lowercase (`.txt`, `.hlp`, `.h`). DOS help sources (CR LF, ^Z end of file) are accepted. The `.hlp` format is the same as in DOS: `make check-help` verifies that `DEMOHELP.TXT` produces a file byte-identical to the original `DEMOHELP.HLP`. The "Overwrite? (y/n)" question is read as an ordinary line from stdin.

## What was changed in the code

- **`tools/convert.py`:** one-off mechanical conversion of the original:
  - file names lowercased, CRLF replaced with LF;
  - `near`, `far`, `huge`, `_FAR`, `_Cdecl` and Borland pragmas removed;
  - explicit `int` added to `const x = 1;`;
  - CP437 bytes in literals replaced with `\ooo`.
- **ASM rewritten in C++:**
  - `tvwrite.cpp`: `writeView` with clipping and shadows;
  - `tvexposd.cpp`, `tvcursor.cpp`, `framelin.cpp`, `tgrmv.cpp`, `ttprvlns.cpp`;
  - `edits.cpp`: the editor's gap buffer;
  - inline asm in `drivers.cpp`, `teditor1.cpp` and `teditor2.cpp`.
- **`source/platform/`:** a new layer replacing the BIOS (INT 10h/16h/33h):
  - `screen.cpp`: output with escape sequences and UTF-8;
  - `keys.cpp`: the key and mouse queues, BIOS key codes;
  - `codepage.cpp`: tables for 437, 866 and 1125;
  - `posix/`: the terminal (termios, signals, size), the decoder of keyboard
    and mouse escape sequences, and `findfirst`, `fnsplit`, `strupr`, `itoa`
    etc. on top of POSIX;
  - `win32/`: the same for the Windows console (console modes, key and mouse
    events, `FindFirstFile`), built with CMake;
  - `driver.h`: what the shared and the system parts give each other.
- **`include/tvcompat.h`, `include/compat/*.h`:** replacements for `dos.h`, `dir.h`, `mem.h`, `iostream.h`, `strstrea.h` and other Borland headers.
- **`TProgram::getEvent`:** handles resizing, flushes the screen and waits up to 30 ms for input instead of busy polling.
- **`TEditor::drawLines`:** virtual, so that a derived editor can colour its text (used by `TColoredEditor`).
- **Mouse wheel:** a new event `evMouseWheel` (0x0020) with the direction in `event.mouse.buttons` (`mwUp`, `mwDown`, `mwLeft`, `mwRight`). It is not part of `evMouse`, so code written for TV 1.0 never sees it. It is a positional event (`positionalEvents`), so it goes to the view under the mouse, and only if that view has `evMouseWheel` in its `eventMask`. `TAdvancedEditor` uses it.
- **Bugs in the original found by GCC and ASan, now fixed:**
  - `va_start` in `messageBox`;
  - returning addresses of local buffers in `helpbase.cpp`;
  - `TParamText::setData` (`&rec`);
  - file time changed when `TFileInfoPane` redraws;
  - `moveBuf` with `attr == 0`;
  - `phone[14]` overflow in `tvg17b`;
  - `TCollection::read`: a local `limit` variable shadowed the member, and `setLimit` copied items from an uninitialised pointer;
  - `TSortedListBox::list()` and other casts through an incomplete type became a `reinterpret_cast` without the virtual-base adjustment;
  - uninitialised `TResourceFile::modified`;
  - `getWord`/`replaceExt` in TVHC returned addresses of local buffers;
  - `new[]`/`delete[]` in `new.cpp`.

## Tests

`tools/tmuxrun.sh` runs a program in a background tmux session and feeds it keys,
mouse clicks and resizes; `tools/smoketest.sh` runs every program this way.
Development and testing were done in Docker (`gcc:13` + tmux):

```sh
sh tools/smoketest.sh
sh tools/tmuxrun.sh bin/tvdemo 100 30 keys:F10 keys:Down shot resize:60x20 shot keys:M-x
```

On Windows `ctest --test-dir build -C Release` runs the tests of the add-ons;
`tvhc` there compiles `help/demohelp.txt` into a file equal to the DOS
`DEMOHELP.HLP` as well.
