Porting guide

How the Linux port differs from the original Borland Turbo Vision 1.0, how to use it in a terminal, and what to change in existing programs.

At a glance

The public interface of the library is the one of Turbo Vision 1.0: the same classes, members, commands, key codes, palettes and stream format. A program written for the DOS version needs changes only where it relied on DOS, on the Borland compiler or on 16-bit sizes. The table summarizes what changed underneath.

KeyboardBIOS INT 16h scan codesTerminal escape sequences decoded into the same BIOS-style kb... codes
MouseMouse driver INT 33hxterm SGR mouse reports (modes 1002 + 1006)
CharactersCode page of the PC (CP437 in the US)8-bit code page inside (437, 866 or 1125), UTF-8 on the terminal

Building and linking

Requirements: g++ with C++11 support (tested with GCC 13 and 15) and GNU make. There are no other dependencies; the terminal is driven directly through termios, so ncurses is not needed.

make            # lib/libtv.a, demos and docdemos in bin/
make lib        # the library only
make DEBUG=1    # -O0 -g
make ASAN=1     # AddressSanitizer + UndefinedBehaviorSanitizer
make check-help # compiles help/demohelp.txt and compares it with the DOS DEMOHELP.HLP
make clean

To build your own program, add both include directories and link the archive with --whole-archive:

TV = /path/to/tvision

g++ -std=c++11 -I$(TV)/include -I$(TV)/include/compat -c myapp.cpp
g++ -o myapp myapp.o -Wl,--whole-archive $(TV)/lib/libtv.a -Wl,--no-whole-archive
Why --whole-archive? Every streamable class registers itself through a static TStreamableClass object. A plain static link drops modules that nothing references, and reading such a class from a stream then fails. The DOS version solved this with __link(), which still works; --whole-archive simply keeps everything.

include/compat/ contains stand-ins for Borland headers (dos.h, dir.h, mem.h, alloc.h, bios.h, conio.h, io.h, iostream.h, fstream.h, iomanip.h, strstrea.h, strstream.h), so most existing #include lines compile unchanged. They all map to tvcompat.h and the standard library.

The library replaces the global operator new/delete (and their array and std::nothrow forms), as the original did, to keep the TV safety pool working. Do not replace them again in your program. When memory runs out, the plain new aborts as in the original; the nothrow forms return 0 and leave the safety pool alone.

Building on Windows

The same sources build on Windows 10 and later with Visual Studio 2022 or later (MSVC) through CMake. Only the terminal driver differs: the library is compiled with source/platform/win32/ instead of source/platform/posix/. Linux keeps the Makefile; CMakeLists.txt is for Windows only.

cmake -B build                          # finds Visual Studio
cmake --build build --config Release    # lib/tv.lib, lib/tvaddons.lib, bin/*.exe
ctest --test-dir build -C Release       # the tests of the add-ons

Visual Studio also opens the directory as it is (File > Open > Folder). Another project uses the libraries through add_subdirectory; the targets tv and tvaddons bring their include directories, compiler options and /WHOLEARCHIVE (the Windows form of --whole-archive) with them:

add_subdirectory( path/to/tvision tvision EXCLUDE_FROM_ALL )
tv_addons_program( myapp myapp.cpp )         # or: tv_program( myapp myapp.cpp )
# or: add_executable( myapp myapp.cpp )  target_link_libraries( myapp PRIVATE tvaddons )

The programs run in Windows Terminal and in the console window (cmd.exe, PowerShell). What differs from Linux:

AreaWindows
ScreenThe same escape sequences and UTF-8 as on Linux: the console takes them once ENABLE_VIRTUAL_TERMINAL_PROCESSING is set (Windows 10 and later). The size is that of the visible window; a new size is noticed by comparing it.
KeyboardKey events of the console (ReadConsoleInput), turned into the same kb... codes. The console gives the state of Shift, Ctrl and Alt with every key, so Shift+arrows select in the editor in any console. AltGr characters are typed as characters. Ctrl+C is a key; Ctrl+Break and closing the window end the program with the console restored.
MouseMouse events of the console: buttons, position, the wheel (evMouseWheel, also sideways). Quick-edit selection is turned off while the program runs.
Redirected stdin / stdoutThe driver opens the console itself (CONIN$, CONOUT$), as Linux would open /dev/tty.
PathsInside the library paths are written with / and start with the drive: C:/Users/..., which Windows takes. \ typed in a dialog is accepted. See Files and paths.

The help files (tvhc) and the object streams are byte-for-byte the same as on Linux and DOS.

Running in a terminal

Any xterm-compatible terminal works: xterm, GNOME Terminal, Konsole, Windows Terminal, PuTTY, iTerm2, tmux and screen, and the Linux console. Over ssh nothing extra is needed. The terminal should use UTF-8.

AspectBehaviour
StartThe terminal switches to full-screen mode when a TProgram (normally your TApplication) is constructed: raw input, alternate screen, auto-wrap off, mouse reporting on. Programs that only use collections or streams keep a normal console.
ExitThe previous terminal state is restored on normal exit, on exit(), and on SIGTERM, SIGHUP, SIGINT, SIGQUIT, SIGSEGV, SIGBUS, SIGFPE and SIGABRT.
SizeRead with TIOCGWINSZ; if that fails, $COLUMNS/$LINES; otherwise 80×25. Widths above 1024 are clipped.
ResizingOn SIGWINCH, TProgram::getEvent() resizes the screen buffer and calls changeBounds() on the application. The desktop, menu bar and status line follow; windows (gfGrowRel) scale; dialogs without a grow mode keep their size and are clipped.
OutputOnly cells that changed since the last frame are sent. When nothing changes, nothing is written, so an idle program causes no ssh traffic.
ColorsThe 16 CGA colors map to ANSI colors 30–37/90–97 (foreground) and 40–47/100–107 (background). Attribute bit 7 means bright background, not blinking.
CursorShown where TView::resetCursor() puts it. Insert mode (sfCursorIns) gives a block cursor, overwrite mode an underline (ESC [ n q).
IdleWhen there is no input, getEvent() calls idle(), flushes the screen and waits up to 30 ms for input instead of polling in a loop.
SuspendTApplication::suspend() gives the normal screen back (for running a shell); resume() takes it again and repaints everything. Resuming after SIGCONT also repaints.

Keyboard and mouse

Terminal input is decoded into the BIOS-style key codes of tkeys.h, so kbF1, kbAltX, kbCtrlLeft and the rest work as before. The decoder understands xterm, VT220, rxvt and Linux console sequences.

  • Esc alone is recognized after 40 ms without a following character.
  • Shift state. DOS programs read the BIOS byte at 0040:0017. The port keeps the Shift/Ctrl/Alt state of the most recent key or mouse event; read it with TEventQueue::getShiftState() (bits kbLeftShift, kbCtrlShift, kbAltShift). A terminal reports modifiers only together with a key, so Shift on its own cannot be detected. (The Windows console reports the modifiers with every key and mouse event.)
  • Mouse. Left and right buttons, dragging, double click (TEventQueue::doubleDelay) and auto repeat work. The wheel gives evMouseWheel events, a port addition (see API differences); views written for Turbo Vision 1.0 never see them. The terminal draws the pointer, so TMouse::show()/hide() do nothing. Holding Shift while clicking usually lets the terminal select text instead.
  • Keys a terminal may not send. Some terminals use Shift+PgUp, Ctrl+Ins, Shift+Ins, Alt+F-keys or F11 themselves. Run bin/keytest to see what yours delivers.

Character set and code pages

Inside the library every character is still one byte, so strings, the editor and the stream formats are unchanged. The byte is interpreted in an 8-bit code page chosen at startup with TVCODEPAGE:

TVCODEPAGECode pageUse
437 (default)IBM PC, USThe original look: frames, ░▒▓, ☺♥, ≡, accented Latin letters
866DOS Cyrillic (Russian)Cyrillic text; no Ukrainian і/ґ
1125DOS Cyrillic (Ukrainian, RUSCII)Ukrainian text with Ґ ґ Є є І і Ї ї
  • Output: each byte is translated to Unicode and sent as UTF-8. The control range 0x00–0x1F is shown with the CP437 glyphs (☺ ☻ ♥ ► ▲ …), as on a PC screen. The box-drawing range 0xB0–0xDF is the same in all three code pages.
  • Input: UTF-8 characters are translated to the code page byte; characters that the code page does not have are ignored.
  • Source code: keep code-page characters in string literals as escapes ("\xC4" or "\304"). A literal typed in a UTF-8 editor is several bytes and draws as several wrong characters.
  • In CP866/1125 the bytes 0xF0–0xFF are Cyrillic, so the CP437 glyph ≡ (0xF0) used for the system menu shows as Ё.
  • Editor files: TFileEditor reads a UTF-8 file whose characters all exist in the code page by converting it to the code page, and saves it back as UTF-8. Other files are edited byte for byte. New files are saved as UTF-8.

Migrating a program step by step

Work through the steps in order; most programs need only the first few. Build with -Wall and fix the warnings: GCC finds most of the problems listed here.

1. Headers and the build

Use lower-case header names (Linux file systems are case-sensitive) and forward slashes. Keep Uses_ + tv.h as before. Old iostream names work through include/compat/; new code can use the standard headers.

Borland C++ / DOS

#include <TV.H>
#include <Dos.h>
#include "..\common\util.h"

Linux port

#include <tv.h>
#include <dos.h>        // shim: tvcompat.h
#include "../common/util.h"

2. Memory-model keywords and pragmas

Remove far, near, huge, _FAR, _Cdecl, interrupt and the Borland pragmas (#pragma option, warn, saveregs, hdrstop). tools/convert.py does this automatically for a whole tree.

Borland C++ / DOS

static char far * near buffer;
void far *operator new( size_t );
#pragma option -Vo-

Linux port

static char *buffer;
void *operator new( size_t );

3. Pre-standard C++

  • Implicit int: const cmMyCmd = 100; → const int cmMyCmd = 100;
  • Old for scope: a variable declared in for( int i ...) is not visible after the loop.
  • friend X; → friend class X;
  • A case label may not jump over an initialized declaration: put the case body in braces.
  • String literals are const char *; parameters that receive them should be const char *.
  • An enum does not convert to a pointer: TWindowInit( streamableInit ) now has its own constructor; similar code in your classes needs one too.
  • typedef enum X { ... }; without a name → enum X { ... };

Borland C++ / DOS

for( int i = 0; i < n; i++ )
    if( a[i] == key ) break;
if( i == n ) notFound();

case evKeyDown:
    char c = getAltChar( ev.keyDown.keyCode );
    ...

Linux port

int i;
for( i = 0; i < n; i++ )
    if( a[i] == key ) break;
if( i == n ) notFound();

case evKeyDown:
    {
    char c = getAltChar( ev.keyDown.keyCode );
    ...
    }

4. Old iostreams

  • ostrstream os( buf, size ); os << ... << ends; keeps working (a fixed-buffer ostrstream is provided in strstrea.h). In new code prefer snprintf or std::ostringstream.
  • stream.getline( ... ) != 0 and similar comparisons with 0 do not compile with standard streams: test !stream.fail() or use the stream in a boolean context.
  • filebuf::openprot, ios::nocreate, ios::noreplace, rdbuf()->fd() do not exist. Get a file size with stat() or by seeking to the end.

Borland C++ / DOS

ifstream f( name );
long size = filelength( f.rdbuf()->fd() );
while( f.getline( line, sizeof line ) != 0 )
    add( line );

Linux port

ifstream f( name );
f.seekg( 0, ios::end );
long size = long( f.tellg() );
f.seekg( 0 );
while( f.getline( line, sizeof line ) )
    add( line );

6. DOS shell and video modes

Borland C++ / DOS

void TMyApp::dosShell()
{
    suspend();
    system( "cls" );
    cout << "Type EXIT to return...";
    system( getenv( "COMSPEC" ) );
    resume();
    redraw();
}

Linux port

void TMyApp::dosShell()
{
    suspend();                      // normal screen back
    const char *sh = getenv( "SHELL" );
    cout << "Type EXIT to return..." << endl;
    system( sh && *sh ? sh : "/bin/sh" );
    resume();                       // full screen again
    redraw();
}

Switching between 25 and 43/50 lines (setScreenMode( smFont8x8 )) has no effect: the terminal decides the size. Remove the command or replace it with a message. Code that assumed exactly 25 rows or 80 columns should use TScreen::screenWidth/screenHeight or the desktop's getExtent(), and views that must follow the window should get a growMode:

TRect r = getExtent();          // clock in the top right corner
r.a.x = r.b.x - 9;
r.b.y = r.a.y + 1;
clock = new TClockView( r );
clock->growMode = gfGrowLoX | gfGrowHiX;    // stays at the right edge
insert( clock );

7. File names and paths

  • Replace \ with / and drop drive letters ("C:\\TV\\DATA" in C source → "/home/user/tv/data" or a relative path).
  • Names are case-sensitive: "DEMOHELP.HLP" is not "demohelp.hlp". The port and its demos use lower-case names and wildcards ("*.tvf").
  • Do not upper-case file names (strupr()) before opening them.
  • Paths can be long: size buffers with MAXPATH (512), not with the DOS value 80.
  • Write text files with '\n'; the C library no longer adds CR.

8. Data records of dialogs

TGroup::getData()/setData() copy the values of the controls one after another into a record, using each control's dataSize(). Under Borland C++ structures were byte-aligned, so a struct matched the controls exactly. GCC aligns fields, and some sizes changed:

ControlDataSize DOS → Linux
TInputLine( r, n )char[n]n → n
TCheckBoxes, TRadioButtonsushort2 → 2
TListBox{ TCollection *items; ushort selection; }6 → 16 (8-byte pointer plus padding; dataSize() is sizeof of that struct)
TMemoushort length; char text[n]2 + n → 2 + n
Your controls storing int / long2 → 4 / 4 → 8

The record must have no padding between the fields. Insert the controls (and declare the fields) so that each field starts at a multiple of its alignment — pointers and long first, then ushort, then char arrays — or add explicit filler controls. A list box entry is simplest as a nested struct of the same shape as the one the list box uses. Check the size against the dialog once; the check catches every mismatch:

struct TListData { TCollection *items; ushort selection; };   // 16 bytes

struct TOptionsRec                 // controls inserted in this order:
{
    TListData list;                // TListBox             offset  0, 16 bytes
    long      limit;               // custom long control  offset 16,  8 bytes
    ushort    flags;               // TCheckBoxes          offset 24,  2 bytes
    ushort    mode;                // TRadioButtons        offset 26,  2 bytes
    char      name[31];            // TInputLine( r, 31 )  offset 28, 31 bytes
};                                 // sizeof may add tail padding: compare the offset

assert( offsetof( TOptionsRec, name ) + 31 == dialog->dataSize() );

For records made only of char arrays, ushort and long fields, #pragma pack( push, 1 ) … #pragma pack( pop ) around the declaration gives the DOS layout without reordering. Do not pack a record that contains list box data: the list box always copies its full, aligned 16-byte structure.

9. 64-bit sizes and pointers

  • int is 4 bytes, long and pointers 8 bytes. Code that stores a pointer in an int/long must use intptr_t; integers passed in message( ..., (void *)value ) should be cast through intptr_t as well.
  • Memory from new T[n] must be released with delete[]; delete of a void * is undefined.
  • Do not rely on 64 KB wrap-around or on sizeof(int) == 2 when reading binary files: use readWord(), int16_t, int32_t.
  • Returning the address of a local array (it happened to work in DOS) breaks with an optimizing GCC; make the buffer static or pass it in.

Borland C++ / DOS

message( owner, evBroadcast, cmColorSet, (void *)color );
...
delete (char *)items;          // allocated with new char[n]

Linux port

message( owner, evBroadcast, cmColorSet, (void *)(intptr_t)color );
...
delete[] (char *)items;

10. Casts between classes with virtual bases

The collection classes use virtual inheritance (TSortedCollection : TNSSortedCollection, TCollection with a virtual TNSCollection base). A C-style cast between such classes when one of them is only forward-declared silently becomes a reinterpret_cast and yields a wrong pointer. Make sure the full class is visible (define its Uses_ macro) and prefer static_cast, which refuses to compile in that case.

Borland C++ / DOS

class TSortedCollection;      // only declared
TSortedCollection *c =
    (TSortedCollection *)listBox->list();

Linux port

#define Uses_TSortedCollection
#include <tv.h>
TSortedCollection *c =
    static_cast<TSortedCollection *>( listBox->list() );

11. Streamable classes

Nothing changes in the pattern (name, build(), read(), write(), a TStreamableClass object). Remember that int written with << is stored in 16 bits and long in 32 bits, exactly as in DOS; values outside these ranges are truncated. Link with --whole-archive or use __link() for classes in your own static libraries.

12. Text and characters

  • Keep box-drawing and other code-page characters as escapes in literals ("\xDA\xC4\xBF").
  • char is signed: compare bytes as (uchar)c == 0xF0, not c == '\xF0' after a conversion to unsigned.
  • Choose TVCODEPAGE to match the language of your data.

13. Checking the result

make ASAN=1                         # sanitizers catch the 64-bit problems

Bugs of the original fixed in the port

These defects were harmless or hidden under DOS and became crashes or wrong results with GCC on 64-bit Linux. They are fixed in the library; your own code may contain similar ones.

WhereProblem
TCollection::read()A local variable limit hid the member, so setLimit() copied items from an uninitialized pointer. Reading any collection from a stream could crash.
TSortedListBox::list(), TFileList::list(), TDirListBox::list()Casts through a forward-declared class became reinterpret_casts and returned wrong pointers.
messageBox(), messageBoxRect() (formatting versions)va_start was given the wrong argument.
THelpTopic::getLine(), wrapText()Returned the address of a local buffer.
TParamText::setData()Stored the address of its parameter instead of the record.
TFileInfoPane::draw()Changed the time stored in the file record while drawing it (AM/PM lost after a redraw).
TDrawBuffer::moveBuf()With attr == 0, wrote without loading the character.
TResourceFilemodified was not initialized.
new.cppArray new[]/delete[] did not use the library allocator; the std::nothrow forms (used by the standard library, e.g. std::stable_sort) now use it too.
getAltCode()The Alt-Space test never matched with a signed char.
TVHCgetWord() and replaceExt() returned local buffers.
TVG17B demophone[14] was one byte too short for its data.
TGroup::shutDown()The subviews are destroyed one after the other, the first inserted first. Hiding the one with the focus gave the focus to another, which then ran with its neighbours already freed: a TScroller or TListViewer inserted after its scroll bars showed the deleted bar when a dialog closed with the focus in an input line. The group now takes the focus away before destroying its subviews and does not move it while they go.
TEditor::drawLines(), TListViewer, TInputLine, THelpViewer, TTerminal, the TVDEMO file viewerLine buffers of 256 cells overflowed in views wider than 256 columns (DOS screens had at most 132), and the editor showed garbage at its right edge.

Known limitations

  • The editor handles files up to 64 KB, as in the original (positions are ushort).
  • No BGI graphics (the TVBGI demo and TVGUID20/21 are not ported).
  • Of the library's own views, none uses the mouse wheel; in the add-ons, TAdvancedEditor does.
  • Some terminals (PuTTY with its defaults) send Shift+arrows as plain arrows, so Shift selection does not work there; select with Ctrl+K B in any editor, or Ctrl+B in TAdvancedEditor. The Windows console does not have this problem.
  • A character takes exactly one cell; characters outside the active code page cannot be shown or typed.
  • Shift, Ctrl and Alt pressed alone are not visible to the program.
  • Some key combinations are taken by the terminal or the ssh client and never reach the program.
  • Raw data files of TVFORMS and similar programs from DOS are not readable (record layout changed); regenerate them.

Tools

ToolPurpose
bin/keytestShows the key codes, shift state and mouse reports decoded from the terminal. Ctrl-C (or q twice) quits.
bin/tvhcHelp compiler: tvhc file.txt [file.hlp [file.h]]. Accepts DOS help sources; the output format is the DOS one.
tools/tmuxrun.shRuns a program in a detached tmux session and sends keys, text, mouse clicks and resizes; prints screen captures. Useful for automated tests.
tools/tvdrive.shThe same from a script file, as a test: wait: holds until a text is on the screen, gone: until it has gone, exit: N checks the exit status; a failed step prints the screen and the program's stderr. A tmux server of its own.
tools/smoketest.shStarts every program, checks that it draws and exits on Alt-X.
tools/convert.pyThe mechanical converter used for the port (lower-case names, LF, memory-model keywords, implicit int, escaped literals). Can be run on your own DOS sources as a first step.
tools/mkdoc/mkdoc.pyGenerates this documentation.
